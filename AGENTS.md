# Nichosi

Открытый клиент для работы с базами данных. В первую очередь MySQL/MariaDB, затем PostgreSQL и SQLite.
Интерфейс в тёмном стиле IDE. Основные функции: подключения, редактирование таблиц, просмотр связей и статистика.
Основной формат поставки — веб-приложение в Docker-образе. Позже планируется настольная версия для Ubuntu на Wails,
использующая то же ядро и фронтенд.

## Язык
- Общайтесь с сопровождающим проекта на русском языке.
- Код, комментарии, идентификаторы, сообщения коммитов и документация должны быть на английском языке.
- Эти инструкции написаны на русском; при их обновлении сохраняйте русский язык.

## Структура репозитория
- `api/openapi.yaml` — ЕДИНЫЙ контракт между backend и frontend, единственный источник истины.
- `backend/` — Go; следуйте правилам из `backend/AGENTS.md`.
- `frontend/` — Svelte + TypeScript + Vite; следуйте правилам из `frontend/AGENTS.md`.
- `deploy/` — Dockerfile и docker-compose для веб-приложения Nichosi.
- `docs/architecture.md` — архитектура и интерфейс Driver. `docs/design/` — изображения-образцы интерфейса.
- `docs/decisions/` — короткие ADR, по одному файлу на решение, с нумерацией.

## Обязательные правила
1. Сначала обновляйте контракт: изменения API начинаются в `api/openapi.yaml`, затем обновляются код и типы TypeScript.
2. Все значения в SQL передавайте параметрами. Идентификаторы обрабатывайте через `Driver.QuoteIdent`. Не вставляйте значения в SQL конкатенацией строк.
3. Не записывайте пароли и DSN в журналы и не возвращайте их в ответах. Секреты допускаются только через переменные окружения или зашифрованное хранилище.
4. Изменения из интерфейса должны проходить через ChangeSet: сначала предварительный просмотр SQL, затем применение одной транзакцией. Таблицы без первичного или уникального ключа доступны в интерфейсе только для чтения.
5. Подключения с `readonly: true` доступны только для чтения. Если `readonly` не задан, используйте режим только для чтения.
6. Для каждого запроса из интерфейса задавайте ограничение числа строк по умолчанию и тайм-аут.
7. Не используйте cgo. Сборки должны быть статическими; для SQLite используйте modernc.
8. Не добавляйте телеметрию и сетевые вызовы, кроме обращений к базам данных пользователя.
9. Не копируйте брендинг, значки и другие материалы третьих лиц. Используйте Lucide или Tabler и проверяйте лицензии.

## Работа с агентами
Описания проектных агентов находятся в `.codex/agents/`.
- `backend-go` отвечает за `backend/`, `deploy/` и реализацию контракта `api/openapi.yaml`.
- `frontend-svelte` отвечает за `frontend/` и разрабатывает его с mock-сервером, созданным по контракту.
- `code-reviewer` проверяет изменения только для чтения.

Главная сессия координирует работу:
1. Согласуйте контракт в главной сессии и зафиксируйте его до параллельной реализации.
2. Делегируйте backend и frontend параллельно только тогда, когда наборы изменяемых файлов не пересекаются.
3. Перед слиянием существенных изменений попросите `code-reviewer` выполнить проверку.
4. Если агенту требуется изменить контракт, он должен внести минимальные изменения в `api/openapi.yaml` и явно сообщить об этом. Главная сессия решает, нужно ли адаптировать другую часть приложения.

## Команды
Список команд приведён в Makefile: `make re` (пересборка и запуск), `make down`, `make run`, `make test`, `make vet`, `make install`, `make dev`, `make types`, `make types-go`, `make mock`. Для просмотра списка используйте `make help`.

## Git
- Делайте небольшие коммиты с повелительным сообщением на английском языке, например `Add keyset pagination for MySQL driver`.
- Не отправляйте изменения в удалённый репозиторий, не используйте force-push и не переписывайте историю без просьбы пользователя.

## Критерии готовности
- Сборка и тесты проходят; `go vet` и `npm run check` завершаются без ошибок.
- Контракт согласован с кодом.
- Если поведение изменилось, документация обновлена.
